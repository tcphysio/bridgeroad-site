BRIDGE ROAD PHYSIOTHERAPY — SITE MAINTENANCE NOTES
==================================================

WHERE THE BUSINESS DETAILS LIVE
-------------------------------
site-config.js is the single place to change:
  - Google Business Profile links (Maps, read reviews, leave a review)
  - the Google Place ID
  - the booking URLs
  - the Google star rating and review count shown on the homepage
  - the fee list used as a cross-check against the booking system

Phone, email and address are ALSO written into every page's HTML, because
search engines need them in the markup. If you change those, search the repo
for the old value and change it everywhere.

FEES
----
fees.html is the source of truth for pricing. No other page repeats the
numbers. If a price changes: update fees.html, update window.BRP.fees in
site-config.js, and update Halaxy.

GOOGLE RATING ON THE HOMEPAGE
-----------------------------
Open site-config.js and find window.BRP.google. Enter the current star
rating, the review count and today's date, copied from the Google Business
Profile. Until you do, the homepage shows only the "Read our Google reviews"
link. Review excerpts are never shown. Re-check the figures monthly.

ADDING PHOTOS
-------------
Images sit in the repository root. Name them descriptively in lowercase with
hyphens, e.g. thihan-chandramohan-bridge-road-physiotherapy.jpg.

For every meaningful image:
  - descriptive filename
  - alt text that describes the image and its context (not keywords)
  - width and height attributes, so the page does not jump while loading
  - loading="lazy" for anything below the fold
  - .webp where you can, landscape ~1200px wide, under ~300KB
  - for a large photo, export two or three widths as separate files
    (e.g. name-600.webp and name-900.webp) and list them in srcset with a
    sizes attribute, so phones download the small one. The portrait on the
    homepage is the example to copy
  - never overwrite an image under the same filename: browsers keep images
    for a week, so returning visitors would keep seeing the old one

Decorative images get alt="".

CONVERSION TRACKING
-------------------
Any element with a data-track attribute fires a named event on click. The
event names are listed in site-config.js. Google Tag Manager
(GTM-MZ36ZHQQ) is loaded on every page and receives these as the custom
event brp_event, with brp_action and brp_detail as data layer variables.
If a new kind of tag is added in GTM, update the privacy policy to match.

THE EMBEDDED MAP
----------------
The map on the homepage and contact page uses the official embed Google
generated for the Bridge Road Physiotherapy listing, so the pin and the info
card are always the business itself.

If the listing ever moves or the map looks wrong:

  1. Open the clinic's listing in Google Maps.
  2. Share -> Embed a map -> Copy HTML.
  3. Take the src="..." value out of that iframe (the long pb= string) and
     paste it over the iframe src in contact.html, the data-map-embed value
     on the homepage's "Show the map" link in index.html, and mapEmbedUrl in
     site-config.js. npm test fails if the three differ.
  4. The same embed carries the listing's coordinates: !2d is the longitude
     and !3d is the latitude. Update lat/lng in site-config.js and the "geo"
     block in the index.html schema to match.

THE ENQUIRY FORM
----------------
The contact and landing page forms post to /api/enquiry, a Vercel Function
in api/enquiry.js. It emails the enquiry through Resend and keeps no copy.
Formspree is no longer used anywhere.

Set these in Vercel -> Project -> Settings -> Environment Variables:

  RESEND_API_KEY   required, from resend.com, starts with "re_"
  ENQUIRY_TO       optional, defaults to thihan@bridgeroad.physio
  ENQUIRY_FROM     optional, defaults to
                   Bridge Road Physiotherapy <enquiries@bridgeroad.physio>

ENQUIRY_FROM has to be on a domain verified in Resend, which means adding
the DNS records Resend gives you for bridgeroad.physio. Without that, Resend
refuses the send and the patient sees an error with the phone number.

The patient's own address is set as Reply-To, so hitting reply in the inbox
goes straight back to them.

If the key is missing or Resend rejects the send, the form tells the patient
it failed and shows the phone number and email address. It never pretends an
enquiry went through when it did not.
